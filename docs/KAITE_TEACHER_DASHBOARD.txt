## 1. Executive Summary

The KAITE Teacher Dashboard provides educators with real-time monitoring, intervention guidance, and curriculum alignment tools to support AI literacy instruction for middle school CTE students. This specification defines the technical requirements, data models, and UI components necessary for development implementation.

| Target Users | Class Size | Module Duration | Time Savings |
|:------------:|:----------:|:---------------:|:------------:|
| CTE Teachers | 25-30 Students | 8-16 Weeks | 4.5 hrs/week |

## 2. Dashboard Architecture Overview

The Teacher Dashboard consists of four primary wireframe screens, each addressing distinct educator needs within the KAITE platform.

### 2.1 Screen Architecture

| Screen | Primary Function | Key Components |
|--------|------------------|----------------|
| **Class Overview** | Real-time class monitoring with aggregate performance metrics | Progress heatmap, engagement metrics, intervention alerts |
| **Individual Progress** | Student-level analytics with at-risk identification | Student roster, Learning Signal Score, intervention tools |
| **Learning Paths** | Knowledge graph visualization with curriculum pacing | Node completion tracking, path efficiency, bottleneck alerts |
| **Reports & Compliance** | Standards alignment and ethical oversight transparency | ISTE/ACTE mapping, bias audit access, consent status |

### 3.2 Intervention Alert System

The dashboard implements a 3-tier alert system for early identification of struggling students. Alerts are generated based on learning analytics and require teacher acknowledgment.

#### 3.2.1 Alert Tier Definitions

| Tier | Trigger Conditions | Visual Indicator | Recommended Action |
|------|-------------------|------------------|-------------------|
| 🔴 **CRITICAL** | 3+ failed assessments OR 5+ days inactive OR mastery <40% | Red banner, audio chime, persistent badge | Immediate 1:1 intervention required |
| 🟠 **WARNING** | 2 failed assessments OR 3 days inactive OR mastery 40-60% | Orange banner, visual badge | Small group scaffolding recommended |
| 🟢 **MONITOR** | 1 failed assessment OR engagement drop >20% | Yellow icon, tooltip only | Passive monitoring, check next session |

#### 3.2.2 Alert Data Model

**Firebase Collection:** `/alerts/{alertId}`

```typescript
interface Alert {
  alertId: string;              // Auto-generated UUID
  studentId: string;            // Firebase Auth UID (pseudonymized)
  classId: string;              // Reference to class document
  tier: "CRITICAL" | "WARNING" | "MONITOR";
  triggerType: string;          // e.g., "failed_assessment", "inactivity"
  createdAt: Timestamp;
  acknowledgedAt: Timestamp | null;
  resolvedAt: Timestamp | null;
  interventionNotes: string;    // Teacher input
}
```

### 3.3 Individual Student View

#### 3.3.1 Learning Signal Score

A composite metric (0-100) aggregating engagement, accuracy, and growth trajectory. Display as large numeric with breakdown bars.

| Component | Weight | Calculation |
|-----------|--------|-------------|
| Engagement | 40% | `(sessions/week × time_on_task × help_seeking_ratio)` |
| Accuracy | 35% | `(quiz_correct / quiz_total × concept_mastery_rate)` |
| Growth | 25% | `(current_mastery - baseline) / baseline × 100` |

#### 3.3.2 Student Status Indicators

- 🟢 **On Track** (green pill): Learning Signal ≥70, no active alerts
- 🟠 **Needs Attention** (orange pill): Learning Signal 50-69 OR WARNING alert
- 🔴 **At Risk** (red pill): Learning Signal <50 OR CRITICAL alert
- 🔵 **Accelerated** (blue pill): Learning Signal ≥90, ahead of pace

## 4. Data Architecture

### 4.1 Firebase Collection Structure

> ⚠️ **Privacy Note:** All student identifiers use pseudonymized Firebase Auth UIDs. No PII is stored in the analytics database per FERPA requirements.

| Collection | Purpose | Update Frequency |
|------------|---------|------------------|
| `/teachers` | Teacher profiles, class assignments, preferences | On profile update |
| `/classes` | Class rosters, aggregate metrics, module progress | Real-time (aggregate) / Daily (computed) |
| `/students` | Individual progress, mastery scores, learning paths | On interaction (node traversal, quiz) |
| `/sessions` | Login/logout times, activity logs, duration | On session start/end |
| `/alerts` | Intervention alerts, acknowledgments, resolutions | On trigger condition met |
| `/assessments` | Quiz responses, scores, confidence ratings | On assessment submission |
| `/knowledgeGraph` | Concept nodes, relationships, difficulty metadata | On curriculum update (admin only) |

### 4.2 Student Progress Document Schema

**Firebase Path:** `/students/{studentId}`

```typescript
interface StudentProgress {
  studentId: string;
  classIds: string[];
  
  // Mastery Tracking
  conceptMastery: {
    [nodeId: string]: {
      score: number;           // 0-100
      attempts: number;
      lastAttempt: Timestamp;
      status: "not_started" | "in_progress" | "mastered";
    }
  };
  
  // Aggregate Metrics
  overallMastery: number;      // Weighted average
  learningSignalScore: number; // Composite 0-100
  nodesCompleted: number;
  totalNodes: number;
  
  // Engagement

  // Path Tracking
  currentPath: string[];       // Node IDs in order

}
```

## 5. Authentication & Authorization

### 5.1 SSO Integration

KAITE supports school-based Single Sign-On through Firebase Authentication with the following identity providers:

1. **Google Workspace for Education:** OAuth 2.0 with domain restriction
2. **Microsoft Azure AD:** SAML 2.0 for district integration
3. **Clever:** Library roster sync for automated class management

### 5.2 Role-Based Access Control

| Role | Dashboard Access | Data Scope |
|------|------------------|------------|
| **Teacher** | Full Teacher Dashboard access, intervention tools, report generation | Assigned classes only |
| **Administrator** | Teacher Dashboard + Admin Dashboard, bias audit access, ROI tracking | School/District wide |
| **Student** | Student Dashboard only (no teacher view access) | Own data only |

### 5.3 Firebase Security Rules (Example)

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Teachers can only read their assigned classes
    match /classes/{classId} {
      allow read: if request.auth != null 
        && request.auth.token.role == "teacher"
        && classId in request.auth.token.assignedClasses;
    }
    
    // Teachers can read/write alerts for their classes
    match /alerts/{alertId} {
      allow read, write: if request.auth != null
        && request.auth.token.role == "teacher"
        && resource.data.classId in request.auth.token.assignedClasses;
    }
    
    // Students can only read their own data
    match /students/{studentId} {
      allow read: if request.auth != null
        && request.auth.uid == studentId;
    }
  }
}
```

## 7. Ethical Oversight Transparency

### 7.1 Bias Audit Access

Teachers have read-only access to bias audit results for their classes via the Reports tab. Audit data is generated quarterly by the Ethical Oversight Team.

- **Demographic Performance Gaps:** Visual display of performance variance across gender, SES, EL status (target: ≤20%)
- **Algorithm Fairness Metrics:** False positive/negative rates for intervention alerts by demographic
- **Content Bias Flags:** Any identified bias issues in knowledge graph content

### 7.2 Privacy Consent Dashboard

Teachers can view consent status for their students:

- **Parental Consent Status:** Active / Pending / Withdrawn (COPPA compliance for <13)
- **Data Collection Scope:** What data is collected, why, and retention period
- **Student Data Access Log:** Audit trail of who accessed student records (FERPA)

### 7.3 Explainability Features

Per DOE and NIST AI RMF requirements, teachers can access:

- **Intervention Trigger Logic:** Why a specific student triggered an alert
- **Learning Path Recommendations:** Knowledge graph reasoning behind suggested paths
- **LLM Response Sources:** Source node references for tutoring explanations

## Appendix B: API Endpoints (Firebase Functions)

### B.1 Computed Metrics

These Cloud Functions run on schedule to compute aggregate metrics:

| Function | Trigger | Purpose |
|----------|---------|---------|
| `computeClassMetrics` | Every 15 minutes | Update class-level aggregates |
| `computeLearningSignal` | On student activity | Recalculate Learning Signal Score |
| `checkAlertTriggers` | On assessment/session end | Evaluate alert conditions |
| `generateWeeklyReport` | Sunday 11pm | Create weekly progress snapshots |

### B.2 Real-time Listeners

```typescript
// Class Overview - Real-time updates
const classRef = doc(db, 'classes', classId);
onSnapshot(classRef, (doc) => {
  updateClassMetrics(doc.data());
});

// Alerts - Real-time with query filter
const alertsQuery = query(
  collection(db, 'alerts'),
  where('classId', '==', classId),
  where('resolvedAt', '==', null),
  orderBy('createdAt', 'desc')
);
onSnapshot(alertsQuery, (snapshot) => {
  updateActiveAlerts(snapshot.docs);
});
```
